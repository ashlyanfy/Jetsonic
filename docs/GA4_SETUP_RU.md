# GA4 для jetsonic.aero — ручная настройка

Идентификатор потока: `G-8MV5KXLR61`
Домен: `jetsonic.aero` (плюс `www.jetsonic.aero`)
Код измерений: [`frontend/analytics.js`](../frontend/analytics.js)

Код отправляет события. Всё остальное — правильный подсчёт пользователей,
отсечение своих, срок хранения, конверсии — живёт в интерфейсе GA4 и **кодом не
настраивается**. Ниже порядок действий сверху вниз; каждый шаг объясняет, что
именно он чинит, потому что половина настроек GA4 по умолчанию стоит так, что
цифры получаются неточными.

Оценка времени: около часа на всё, плюс сутки ожидания первых данных.

---

## 0. Прежде чем начать

Нужен доступ уровня **«Администратор»** к ресурсу GA4, где живёт поток
`G-8MV5KXLR61`. Уровень «Редактор» не даёт менять хранение данных и настройки
ресурса — половина шагов ниже будет недоступна.

Проверить: **Администратор → Ресурс → Управление доступом** — напротив вашей
почты должна стоять роль «Администратор».

---

## 1. Базовые настройки ресурса

**Администратор → Ресурс → Настройки ресурса**

| Поле | Поставить | Зачем |
|---|---|---|
| Часовой пояс | `(GMT+04:00) Дубай` | Сутки в отчётах должны совпадать с рабочим днём компании. Иначе заявка, поданная вечером в Дубае, попадёт во «вчера», и дневные графики будут врать. |
| Валюта | `Доллар США (USD)` | Сделки в USD; смена валюты задним числом не пересчитывает исторические данные. |
| Отрасль | `Бизнес и промышленность` | Влияет только на отраслевые сравнения, но без него они бессмысленны. |

Менять часовой пояс позже **нельзя без потери сопоставимости**: GA4 не
пересчитывает прошлое, в отчётах появится стык. Поэтому это первый шаг.

---

## 2. Хранение данных — самая частая потеря

**Администратор → Ресурс → Хранение данных**

Поставить **14 месяцев** вместо стандартных 2.

По умолчанию GA4 удаляет пользовательские данные через **два месяца**. Сводные
отчёты остаются, но любое исследование «откуда пришли те, кто оставил заявку в
марте» в мае уже невозможно — данных физически нет. Ретроактивно это не
чинится: включив 14 месяцев в июне, вы не вернёте апрель.

Также включить **«Сбрасывать данные о пользователе при новом событии»** — тогда
активный посетитель не «протухает» посреди цикла сделки.

---

## 3. Отчётная идентификация — от неё напрямую зависит число пользователей

**Администратор → Ресурс → Отчётная идентификация**

Выбрать **«Только по устройству»** (Device-based).

Вариант по умолчанию — «Смешанная» (Blended): там, где данных не хватает, GA4
**достраивает пользователей моделью машинного обучения**. Числа выглядят
глаже, но это оценка, а не факт. Для B2B-сайта с десятками заявок в месяц
модель работает на слишком малой выборке, и «пользователи» перестают быть
пересчитываемой величиной.

«Только по устройству» даёт то, что реально измерено. Если позже понадобится
сравнить — режим переключается в любой момент и **применяется ко всей истории**,
так что ничего не теряется.

---

## 4. Google Signals — выключить

**Администратор → Ресурс → Сбор данных → Сбор данных Google Signals**

Оставить **выключенным**.

Signals добавляет демографию, но включает **порог отображения**: как только в
отчёте мало пользователей, GA4 **скрывает строки целиком**, чтобы никого не
деанонимизировать. На трафике этого сайта под порог попадёт большинство
срезов — вы получите отчёты с дырами вместо демографии.

Включать имеет смысл, только когда суточная посещаемость перевалит за несколько
тысяч.

---

## 5. Внутренний трафик — чтобы «пользователи» не считали свою команду

Два механизма, ставить оба: они закрывают разные дыры.

### 5.1. Правило по IP (офис, постоянный адрес)

**Администратор → Поток данных → выбрать поток → Настройки тега → Показать все →
Определить внутренний трафик → Создать**

- Название правила: `Офис Jetsonic`
- `traffic_type`: `internal`
- Тип совпадения: `IP-адрес равен` → указать внешний IP офиса

Узнать IP офиса можно, открыв в браузере на офисном интернете любой сервис
вида «what is my ip».

### 5.2. Метка на устройстве (телефоны, ноутбуки, роуминг)

Правило по IP не работает для мобильного интернета и удалённой работы — адрес
меняется. Поэтому в `analytics.js` встроен второй механизм.

Каждый сотрудник **один раз** открывает на своём телефоне и ноутбуке:

```
https://jetsonic.aero/?ga_internal=1
```

Устройство запоминается в `localStorage` навсегда. Дальше все его события
уходят с `traffic_type=internal` и отсекаются тем же фильтром.

Отменить метку: `https://jetsonic.aero/?ga_external=1`

Если нужно полностью выключить сбор на устройстве (не пометить, а заглушить):
`https://jetsonic.aero/?ga_optout=1`, вернуть — `?ga_optin=1`.

### 5.3. Включить сам фильтр — шаг, который забывают

**Администратор → Ресурс → Фильтры данных**

Фильтр `Internal Traffic` создаётся автоматически, но стоит в состоянии
**«Тестирование»** — то есть **ничего не фильтрует**, только помечает.

Открыть его и переключить в **«Активный»**.

> ⚠️ Фильтры данных в GA4 работают **только вперёд**. Уже собранные события
> они не вычищают. Поэтому включать нужно до того, как накопится статистика,
> а не после.

## 6. Enhanced Measurement — отключить то, что задваивает

**Администратор → Поток данных → выбрать поток → Улучшенная статистика →
шестерёнка**

| Переключатель | Поставить | Почему |
|---|---|---|
| Просмотры страниц | **вкл** | Базовый счётчик, нужен. |
| Прокрутки | **выкл** | Штатное событие `scroll` срабатывает один раз на 90%. В коде есть `scroll_depth` с порогами 25/50/75/90 — он информативнее. Два источника рядом путают отчёты. |
| Исходящие клики | **выкл** | Код отправляет `outbound_click`, `whatsapp_click`, `phone_click`, `email_click` — с указанием места на странице. Штатное событие даёт голый URL и дублирует их. |
| Поиск по сайту | **выкл** | Поиска на сайте нет. |
| Взаимодействие с видео | **выкл** | Видео нет. |
| Скачивание файлов | **выкл** | Файлов для скачивания нет; форма файлы принимает, а не отдаёт. |
| **Взаимодействия с формами** | **выкл** | Критично. Штатные `form_start` и `form_submit` срабатывают на любой отправке, включая ботов и неудачные. Код отправляет свои `form_start`, `rfq_submit` и `generate_lead` — с фильтрацией ботов и проверкой, что API реально принял заявку. |

Смысл: **один сигнал — один источник**. Там, где включены оба, вы получаете два
разных числа для одного действия и не знаете, какому верить.

## 7. Нежелательные переходы — чтобы WhatsApp не рвал сессии

**Администратор → Поток данных → выбрать поток → Настройки тега → Показать все →
Список нежелательных переходов**

Добавить по условию «Домен перехода содержит»:

```
jetsonic.aero
wa.me
whatsapp.com
```

Что это чинит: посетитель нажимает WhatsApp, уходит в мессенджер, возвращается
на сайт. Без этой настройки GA4 видит переход с `wa.me`, **закрывает старую
сессию и открывает новую** с источником «whatsapp / referral». Один человек
превращается в два визита, а исходный источник (поиск, реклама) теряется.

`jetsonic.aero` в списке нужен для переходов между `www` и без `www`.

## 8. Пользовательские параметры — без них половина данных не видна

**Администратор → Ресурс → Пользовательские определения → Создать специальный
параметр**

Событие может нести любые параметры, но **в отчётах они не появятся, пока не
зарегистрированы здесь**. Это не влияет на сбор — данные копятся с первого дня —
но увидеть их можно только после регистрации, и **задним числом отчёт не
покажет то, что было до регистрации**. Поэтому делать сразу.

Область у всех — **«Событие»**.

| Название параметра | Параметр события | Что показывает |
|---|---|---|
| Тип страницы | `page_type` | home, contact, parts, aog, thank_you, not_found |
| Язык страницы | `page_language` | en или ar |
| Место ссылки | `link_placement` | hero, header_nav, mobile_nav, footer, contact_card, cta_band |
| Текст ссылки | `link_text` | подпись нажатой ссылки |
| Домен ссылки | `link_domain` | для исходящих переходов |
| Место CTA | `cta_placement` | где стояла нажатая кнопка |
| Текст CTA | `cta_text` | подпись кнопки |
| Место навигации | `nav_placement` | header_nav, mobile_nav, footer |
| Канал связи | `contact_channel` | whatsapp, phone, email |
| Глубина прокрутки | `percent_scrolled` | 25, 50, 75, 90 |
| Секция | `section_id` | какой блок страницы досмотрели |
| Позиция секции | `section_position` | порядковый номер блока |
| Тип запроса | `request_type` | Standard RFQ, AOG Request, Repair / Exchange, Documentation / Logistics |
| Срочность | `urgency` | Routine, Priority, AOG, Required within 24 hours |
| Тип самолёта | `aircraft_type` | из формы RFQ |
| Есть вложение | `has_attachment` | yes / no |
| Есть альтернативный PN | `has_alternate_pn` | yes / no |
| Последнее поле | `last_field` | где бросили заполнение формы |
| Код ошибки | `error_status` | HTTP-код отказа API |
| Тип ошибки | `error_type` | api_status или network |
| Страница входа в форму | `entry_page` | откуда пришли на форму |
| Ненайденный путь | `not_found_path` | что искали и не нашли |

Лимит ресурса — **50 параметров области «Событие»**. Здесь 21, запас большой.

## 9. Ключевые события (конверсии)

**Администратор → Ресурс → Ключевые события → Создать ключевое событие**

Кнопка появляется только после того, как событие хотя бы раз пришло. Поэтому
порядок такой: сначала задеплоить, потом пройти по сайту (см. раздел 11), потом
вернуться сюда.

Отметить как ключевые:

| Событие | Что означает |
|---|---|
| `generate_lead` | **Главная конверсия.** Заявка RFQ дошла до API и принята. |
| `whatsapp_click` | Обращение в WhatsApp. |
| `phone_click` | Звонок с сайта. |
| `email_click` | Письмо с сайта. |

`rfq_submit` ключевым **не делать**: он срабатывает на попытке отправки, включая
те, что упали с ошибкой. Иначе конверсии будут завышены. Он нужен как
знаменатель — сравнивая `rfq_submit` и `generate_lead`, вы видите долю
технических отказов.

### Ценность лида (по желанию)

Если нужна денежная оценка в отчётах — открыть `generate_lead` →
**«Настроить ценность ключевого события»** → задать фиксированную сумму,
например среднюю маржу с закрытой сделки, умноженную на конверсию заявки в
сделку. Код специально **не отправляет** `value`: выдуманное число в отчёте о
доходе хуже, чем его отсутствие.

## 10. Отладочный просмотр

**Администратор → DebugView**

Чтобы страница попала в DebugView, открыть её с параметром:

```
https://jetsonic.aero/?ga_debug=1
```

События появляются в реальном времени, в течение нескольких секунд. Это
единственный способ проверить настройку сразу, не дожидаясь суток.

Параметр `ga_debug=1` также **разрешает отправку с любого хоста** — с
`localhost` или тестового `sslip.io`. В обычном режиме код с них молчит, чтобы
разработка не попадала в статистику.

## 11. Приёмка: что пройти руками после деплоя

Открыть DebugView (раздел 10) в одном окне, сайт с `?ga_debug=1` — в другом, и
проверить по списку:

- [ ] Открыть главную → пришёл `page_view` с `page_type=home`
- [ ] Пролистать главную до конца → пришли `scroll_depth` со значениями 25, 50, 75, 90 — **по одному разу каждое**
- [ ] По ходу прокрутки → пришли `section_view` с разными `section_id`
- [ ] Нажать WhatsApp в подвале → `whatsapp_click`, `link_placement=footer`
- [ ] Нажать телефон в подвале → `phone_click`
- [ ] Нажать почту → `email_click`
- [ ] Переключить язык на арабский → `language_switch`, `language_from=en`, `language_to=ar`
- [ ] Нажать пункт нижнего меню на телефоне → `nav_click`, `nav_placement=mobile_nav`
- [ ] Открыть `/contact/`, кликнуть в поле «Your name» → `form_start` (**один раз**, повторные клики по полям его не повторяют)
- [ ] Прикрепить файл → `rfq_attachment_added`
- [ ] Отправить форму → `rfq_submit`, затем на `/thank-you.html` → `generate_lead` с `request_type` и `urgency`
- [ ] Обновить `/thank-you.html` клавишей F5 → **`generate_lead` не повторяется**
- [ ] Открыть `/thank-you.html` прямой ссылкой в новой вкладке → **`generate_lead` не приходит**
- [ ] Открыть несуществующий адрес `/qwerty` → `page_not_found` с `not_found_path=/qwerty`
- [ ] Начать заполнять форму и закрыть вкладку → `form_abandon` с `last_field`

Два пункта про `/thank-you.html` — самые важные. Именно они доказывают, что
конверсии не завышаются: заявка засчитывается один раз и только когда она
действительно была.

## 12. Что код сознательно не делает

| Не делает | Почему |
|---|---|
| Не отправляет имя, почту, телефон, номер детали | Правила Google запрещают передавать персональные данные в GA4; за нарушение удаляют данные и блокируют аккаунт. В событиях только тип запроса, срочность и признаки «есть/нет». |
| Не считает ботов с заполненной ловушкой | Поле `bot-field` в форме — приманка. Заполнено — значит бот; события заявки подавляются целиком. |
| Не отправляет с автоматизированных браузеров | `navigator.webdriver` выдаёт Playwright, Puppeteer, Selenium. Мониторинг сайта не должен считаться посетителями. |
| Не отправляет с непроизводственных хостов | Работа на localhost и тестовом `sslip.io` в статистику не попадает. |
| Не показывает баннер согласия | См. ниже. |

### Про согласие на cookie — решение за владельцем

Сейчас в коде: аналитические cookie **разрешены**, рекламные — **запрещены**.
Баннера нет.

Это осознанный выбор под аудиторию сайта — ОАЭ, Казахстан, Центральная Азия. Для
посетителей из **ЕС и Великобритании** формально требуется явное согласие даже на
аналитические cookie.

Если решите добавить баннер, менять нужно одно место в
[`frontend/analytics.js`](../frontend/analytics.js) — блок
`gtag('consent', 'default', ...)`: поставить `analytics_storage: 'denied'`, а
после нажатия «Принять» вызвать:

```js
gtag('consent', 'update', { analytics_storage: 'granted' });
```

GA4 сам дошлёт накопленные события. Отдельно ставить баннер и переписывать
логику измерений не придётся.

## 13. Что смотреть в отчётах через неделю

**Отчёты → Взаимодействие → События** — общая картина.

Полезнее собрать своё исследование: **Исследования → Пустое**.

Три среза, которые отвечают на вопросы бизнеса:

1. **Откуда идут заявки.** Строки: `Источник/канал сессии`. Столбцы:
   `Пользователи`, `generate_lead`. Показывает, какой канал приносит не трафик,
   а деньги.

2. **Что делают до обращения в WhatsApp.** Строки: `page_type`. Столбцы:
   `whatsapp_click`, `phone_click`. Показывает, с какой страницы люди берутся за
   телефон — обычно это не та страница, которую считают главной.

3. **Где отваливается форма.** Строки: `last_field`. Столбец: `form_abandon`.
   Прямо называет поле, на котором люди сдаются. Сравнить с `form_start` и
   `generate_lead` — получится воронка формы.
